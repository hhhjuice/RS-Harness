# v0.0.1——基本 Loop 对话与 session 记录

## 1. 文档信息

- 版本：`v0.0.1`
- 标题：基本 Loop 对话与 session 记录
- 状态：已验收
- 日期：2026-09-18
- 上游设计文档：[`LangChain重构方案.md`](/Users/hgz/WorkSpace/RS-Harness/docs/LangChain重构方案.md)

### 阶段目标

在空仓库中建立最小可运行的 LangChain 应用，实现无工具文本 Agent、持久多轮上下文、RSH session 元数据、本地运行记录和基本 CLI。

### 完成标准

文本单轮、多轮和进程重启后的续聊均成功；同一 `thread_id` 保留上下文，不同 `thread_id` 相互隔离；输入、回答、失败和模型调用记录可查看；运行记录不参与模型上下文恢复。

## 2. 阶段边界

### 本阶段实现

- Python 3.12+、uv、TOML/Pydantic 配置。
- 无工具的 `langchain.agents.create_agent`。
- 官方 Chat Model 真实调用。
- SQLite Checkpointer 和 `thread_id`。
- session 元数据。
- 本地 `trajectory.jsonl` 运行记录。
- Typer 交互、单次请求和 session 管理 CLI。

### 本阶段排除

- 基础工具。
- `AgentMiddleware`、Todo、Permission。
- 多模态输入。
- SubAgent。
- 旧 API 兼容。
- 自定义消息历史、审计系统和外部轨迹平台。

本阶段的模型上下文唯一来源是 LangGraph Checkpointer。`trajectory.jsonl` 只供查看，不用于恢复历史、判断执行状态、重放请求或触发重试。

### 3.3 session 与 Checkpointer

**目标**

建立 RSH session 元数据和 LangGraph 持久状态之间的明确边界。

**计划修改**

- `src/rs_harness/sessions/catalog.py`
- `src/rs_harness/sessions/checkpoints.py`

**目录布局**

```text
sessions/
  checkpoints.sqlite3
  <session_id>/
    session.json
    trajectory.jsonl
```

**`session.json` 最小字段**

```json
{
  "session_id": "...",
  "status": "running",
  "workdir": "...",
  "model": "...",
  "created_at": "...",
  "updated_at": "...",
  "closed_at": null
}
```

**规则**

- RSH 只保存 `session_id`；调用框架时将它作为 `configurable.thread_id`，不另行维护 `thread_id`。
- session 生命周期为 `running` 或 `closed`。
- 创建、打开、列出和关闭由 `catalog` 负责。
- session 元数据不保存模型消息历史。
- 空文本输入不得自动创建 session。
- 关闭后的 session 不得继续交互。
- 同一 session 同时有其他交互时返回 `session_busy`，不得重复调用模型。

**Checkpointer 调用配置**

```python
{
    "configurable": {
        "thread_id": session.session_id,
    }
}
```

### 3.4 Agent 与应用入口

**目标**

用官方 `create_agent` 驱动无工具文本对话，不复制旧项目的执行循环。

**计划修改**

- `src/rs_harness/agents/main.py`
- `src/rs_harness/application.py`
- `src/rs_harness/inputs.py`

**Agent 边界**

- 使用官方 Chat Model。
- `tools=[]`。
- 不注册 Middleware。
- 不实现自定义模型—工具循环。
- 不从 trajectory 或 RSH 文件读取历史消息。

**应用调用流程**

```text
CLI 输入
→ 打开或创建 session
→ 构造本轮 HumanMessage
→ 使用 thread_id 调用 agent.ainvoke
→ 从返回 state 读取最终 AIMessage
→ 返回 InteractionResult
```

**接口约定**

```text
application.ask(session_id, text) -> InteractionResult
application.create_session(workdir, config) -> Session
```

### 3.5 运行记录

**目标**

通过 LangChain 官方 callback 观察接口记录本地开发运行轨迹，同时保持记录和模型状态解耦。

**计划修改**

- `src/rs_harness/sessions/recording.py`

**记录事件**

- 用户输入。
- 模型调用开始、结束和错误。
- 最终回答。
- 交互成功或失败。
- `interaction_id`、`run_id`、`parent_run_id`。

**事件格式**

```json
{
  "event_id": "...",
  "interaction_id": "...",
  "timestamp": "...",
  "session_id": "...",
  "event": "user_input|model_start|model_end|interaction_succeeded|interaction_failed",
  "run_id": "...",
  "parent_run_id": null,
  "payload": {}
}
```

记录器应将事件转换为 JSON 可序列化数据，并避免写入 API key。记录写入失败时只报告记录错误，不重新调用模型。

### 3.6 CLI

**目标**

提供本地单用户交互、单次请求和 session 管理入口，保留旧项目熟悉的命令名，但不承诺旧 API 或输出完全兼容。

**计划修改**

- `src/rs_harness/cli.py`

**命令**

- `rsh`：交互模式。
- `rsh ask TEXT`：单次请求，可通过 `--session-id` 续聊。
- `rsh create-session`：显式创建空 session。
- `rsh list-session`：列出 session 元数据。
- `rsh close-session --session-id ID`：关闭 session。

**交互命令**

- `/help`
- `/status`
- `/quit`
- `/exit`
- `/close`

交互模式首次收到非空输入时才创建 session。阶段 1 不提供图片、工具、审批、Todo 或 SubAgent 参数。

## 4. 接口和数据格式

### 4.1 Session API

```text
catalog.create(...) -> Session
catalog.open(session_id) -> Session
catalog.list() -> list[Session]
catalog.close(session_id) -> Session
```

### 4.2 InteractionResult

交互结果至少包含：

- `session_id`
- `interaction_id`
- `status`
- `answer`
- `error`
- `session_status`

错误状态必须能区分配置错误、session 错误、模型调用错误和记录错误。

### 4.3 Agent 调用

每次调用只提交本轮新增消息，并在调用配置中传递 `configurable.thread_id`。应用层不得维护第二份消息历史。

### 4.4 CLI JSON 输出

`--json` 输出结构化 session 或交互结果；不得包含 API key、完整配置密钥或内部凭据。

### 6.5 修复 CLI 第二轮事件循环关闭

**状态：代码修复、本地回归与三轮真实模型验证均通过**

**问题与原因：**

- 交互入口每轮调用 `asyncio.run(ask(...))`，每轮返回后都会关闭事件循环。
- 当前 `langchain-openai` 缓存默认异步 HTTP 客户端，第二轮可能复用绑定在已关闭循环上的连接，出现 `RuntimeError: Event loop is closed`。
- 之前的双轮应用测试在同一测试事件循环中使用 Fake Model，单轮 live 也未覆盖连续 CLI 输入，因此没有检出此问题。

**实际修改：**

- `src/rs_harness/cli.py`：将 `_interactive` 改为异步函数，仅在交互入口调用一次 `asyncio.run`；用户输入循环内逐轮 `await ask(...)`，退出交互时才关闭事件循环。
- `tests/integration/test_interactive.py`：使用绑定事件循环的测试模型，覆盖新建会话和已有历史的 `--session-id` 续聊，检查两轮回答、传入模型的历史、interaction ID 与退出后的资源关闭。
- `tests/live/test_live_smoke.py`：将单轮应用调用扩展为 CLI 连续三轮对话，检查后两轮能返回第一轮给定的记忆标识；数据仅写入临时会话。
- `README.md`：补充交互模式、多轮续聊和更新后的 live 测试说明。

### 6.7 合并会话标识与持久化职责检查

**状态：已完成并验证**

**实际修改：**

- `SessionMeta` 与 `Session` 不再保存或暴露独立 `thread_id`。新 `session.json`、trajectory 事件及 CLI 输出只保留 `session_id`。
- 调用 Agent 时直接使用 `{"configurable": {"thread_id": session.session_id}}`。框架要求的参数名和 SQLite Checkpointer 内部结构保持不变。
- 移除额外写入 Checkpoint 元数据的 `session_id`，避免重复框架配置中的会话标识；保留用于关联单次交互的 `interaction_id`。
- 当前开发版本不迁移旧 `thread_id` 元数据；未知字段按 `extra="forbid"` 处理。session 目录名和 `session_id` 不一致时拒绝打开或从列表中排除。

**职责检查结果：**

| 数据 | 职责 | 冗余判断 |
| --- | --- | --- |
| `session.json` | 保存目录、模型标识、创建/更新时间与关闭状态 | 不保存消息历史；已去除重复 ID |
| SQLite Checkpoint | 官方 saver 保存、恢复 messages 和框架状态 | 没有自建消息存储或恢复逻辑；已去除额外的业务 ID 元数据 |
| `trajectory.jsonl` | 记录本次输入、模型调用、回答、错误及调用关系 | 输入输出与 Checkpoint 部分重叠，但属于可查看的观测副本，不用于恢复上下文 |
| CLI 输入历史 | 供上下方向键编辑本次进程输入 | 仅保存在内存中，不用于自动拼接模型历史 |

源代码检查确认：应用每轮只提交一个新的 `HumanMessage`，不读取 trajectory；模型开始事件只记录消息数量等信息，不逐轮导出完整历史。模型完成事件与交互完成事件分别表示模型调用结果和应用最终结果，继续保留；它们不构成第二套上下文实现。框架自身的 Checkpoint 版本与快照由官方 saver 管理。
