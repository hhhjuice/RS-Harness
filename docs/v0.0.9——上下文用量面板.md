# v0.0.9——上下文用量面板

## 1. 版本目标与交付状态

- 目标版本：`v0.0.9`，前置版本为 `v0.0.8`。
- 实施与记录日期：2026-10-08。
- 状态：功能已实现，审查修复后 38 项专项测试通过；此前全量离线回归有 7 项既有测试资源缺失导致的初始化错误，详见第 8 节。

本版增加 `/context`，展示当前主 session 下一轮模型请求将携带的上下文，包括最近一次模型回复。用户能直接看到分类 token 估算、总窗口、剩余量和占用百分比，界面采用单个紧凑面板。

统计依据当前配置、Checkpoint 消息和已启用工具。查询不调用模型、不执行工具、不连接 MCP、不向消息历史追加内容，也不读取轨迹日志来恢复上下文。历史 API 请求的 token 用量不累计为当前上下文。

版本声明同步到 `pyproject.toml`、`src/rs_harness/__init__.py`、`uv.lock` 中的项目条目和 README。新增直接依赖 `rich>=13,<16`，沿用锁定的 Rich 15.0.0，其余依赖版本不因本功能调整。

界面规则：

- 顶部展示估算已用量、总容量和整体百分比；下方展示单条用量条、剩余量及分类表。有图片时增加 `Images` 行。
- `Window` 列表示该分类占总窗口的百分比，不是占已用量的比例。数字右对齐，百分比保留一位小数；分项百分比的显示值可能存在舍入差异。
- 正常用量条为蓝色，达到 60% 显示黄色，达到 90% 显示红色。超过容量时仍展示真实百分比，进度条封顶，剩余量为零。
- 面板宽度最多 76 列；低于 56 列使用紧凑摘要及短标签，低于 40 列省去外框。进度条用实心和浅色方块区分已用、剩余，在无颜色输出中仍可辨认。
- 非 TTY 或设置 `NO_COLOR` 时，CLI 输出不带颜色。模型名称按普通文字展示，控制字符被转义，不解析为 Rich markup。

颜色阈值按归档时的代码记录为 60% / 90%；原计划为 80% / 95%。本次文档与版本更新保留当前实现。

命令只接受 `/context`，额外参数返回 `Usage: /context`；无 session 时返回 `No session`，不自动创建会话。已创建但尚无消息的 session 会统计基础提示、Skill 目录和本地工具定义。配置、会话、MCP 恢复信息或 SQLite 读取发生预期错误时，CLI 显示错误后继续接受输入。

`/help` 列出此命令。本版没有独立的 `rsh context` 子命令或 JSON CLI 入口；审批提示符继续使用原有批准/拒绝协议。

## 3. 分类统计口径

分类互斥，分类整数用量相加等于总已用量。

| 分类 | 计入内容 | 边界 |
| --- | --- | --- |
| `System` | 基础系统提示、Todo/MCP 等框架指令、带来源标记的 Stop Hook 续跑消息 | Skill 目录与加载指引划入 `Skills` |
| `User` | 用户消息中的文本及其消息格式开销 | 工具图片转换出来的消息不计作用户输入 |
| `Assistant` | 主模型历史回复及工具调用名称、参数 | 只计入实际历史，不直接累加服务商的输出 token 数 |
| `Tool schemas` | 当前可见工具的名称、说明、参数 schema；包含基础工具、middleware 工具、委派入口及已启用的 MCP 工具 | 未连接 MCP 服务的工具定义不计入 |
| `Tool results` | 普通工具返回、工具错误、委派结果和图片工具说明文字 | 成功的 `load_skill` 返回划入 `Skills`；artifact 不计入 |
| `Skills` | 当前技能目录、加载指引和历史中成功加载的完整 Skill 正文 | 未加载正文不计入；重复加载按历史实际出现次数计算 |
| `Images` | 用户输入或工具投影消息中的图片块 | 单独估算，不把 base64 字符串当作文本 |

通用 `read_file` 读取的 Skill 关联文件属于普通工具返回，不根据路径猜测为 Skill 正文。已加载 Skill 从 Checkpoint 统计，原文件删除后，历史正文仍然保留；当前可用技能目录则重新按配置扫描。

子代理上下文独立。主会话只统计 `delegate_task` 的调用参数和返回结果，不遍历子图历史、子代理系统提示或子模型 usage。主图状态中的 Todo、连接元数据和校准记录本身不作为额外消息重复计入。

图片统计复用实际 `read_image` 消息投影，避免把同一图片同时作为工具内容和新增用户图片消息计算。投影产生的文字带 `rsh_context_source=tool_results` 来源标记；Stop Hook 注入消息使用 `system` 标记。标记供归类使用，不改变消息角色和权限。

## 4. 本地估算与输入用量校准

### 4.1 原始估算

`estimate_categories` 使用 LangChain 的 `count_tokens_approximately`，工具通过 `convert_to_openai_tool` 转为模型可见定义。系统消息中的 Skill 独立文本块以移除前后的估算差额划入 `Skills`，避免重复计算整条系统消息的格式开销。

对内容块形式的 AI 消息，如果工具调用保存在独立的 `tool_calls` 列表而未嵌入内容块，估算器补计这些调用；已经嵌入的调用不再重复计入。

Responses API 的 `function_call` / `custom_tool_call` 内容块使用 `call_id` 与 `tool_calls[].id` 对应，不能使用响应项自身的 `id` 去重；标准 `tool_call` 和 Anthropic `tool_use` 仍使用 `id`。混合消息只补计尚未嵌入的调用，原消息保持不变。

当前锁定估算器对每张图片默认计入 85 tokens。代码通过正常估算与 `tokens_per_image=0` 的差额提取图片分类，不下载 URL、不解码或按分辨率计费。所有结果仍是近似值，面板始终显示 `≈`。

### 4.2 主模型校准

`ContextUsageMiddleware` 只装入主代理，位于改变模型输入的 middleware 之后、`StopHookMiddleware` 之前，读取最终请求。主模型成功返回有效正整数 `usage_metadata.input_tokens` 时，通过 `ExtendedModelResponse` 和 `Command(update=...)` 保存：

```text
context_calibration = {
    model_key,
    estimated_input_tokens,
    input_tokens
}
```

`model_key` 是配置模型名与规范化 endpoint 的 SHA-256 摘要；校准记录不保存 API key、原始提示或整份请求。`estimated_input_tokens` 使用与查询相同的分类估算器，包含当次真实可见的提示、消息和工具。

查询时，匹配模型且两个输入计数均有效的最近样本用于统一缩放：

```text
factor = input_tokens / estimated_input_tokens
category_tokens = round(raw_category_tokens * factor)
used_tokens = sum(category_tokens)
```

没有可用样本时 `factor=1`，返回 `estimation_method="approximate"`；有效校准时为 `"calibrated"`。模型或 endpoint 不匹配时不采用样本。最近一次成功模型响应没有有效输入用量时，写入空校准记录，避免继续沿用更早的样本；调用失败未产生新响应时不生成样本。

校准不使用 `output_tokens` 或 `total_tokens`，不累加多次调用，也不扣除缓存命中的输入。查询仍重新统计当前历史，包括最新回复；不会直接把上一次请求的输入计数当作当前总量。校准改善总量估算，不意味着服务商提供了真实的分类账单，尤其图片和不同内容类型之间仍有误差。

## 5. 装配复用与只读查询

主要组件：

| 位置 | 职责 |
| --- | --- |
| `src/rs_harness/context_usage.py` | 分类、容量解析、校准应用、`ContextUsage` 数据模型及只读查询 |
| `src/rs_harness/agents/context_usage.py` | 主模型请求的校准采样及 Checkpoint 状态字段 |
| `src/rs_harness/agents/main.py` | `AgentComponents`、共享装配及无 I/O 的请求投影 |
| `src/rs_harness/agents/subagent.py` | 提取 `make_delegate_tool`，查询可复用实际委派 schema 而不构建子图 |
| `src/rs_harness/agents/mcp.py`、`src/rs_harness/mcp.py` | 共享 MCP 提示投影、已启用工具 schema 快照及本地配置校验 |
| `src/rs_harness/sessions/checkpoints.py` | SQLite 只读连接入口 |
| `src/rs_harness/context_display.py`、`src/rs_harness/cli.py` | 面板渲染、交互命令与错误处理 |

查询流程：

1. 打开 session 元数据，核对当前子代理定义摘要与 session 一致。
2. 若 Checkpoint 文件存在，使用 `mode=ro` 打开 SQLite，跳过建表和 journal-mode 初始化；只读取根命名空间 `checkpoint_ns=""`。
3. 获取最新 Checkpoint，并在内存中应用已完成、尚未合入快照的 pending writes：消息使用 `add_messages`，MCP 连接使用原有 reducer，校准样本按状态更新覆盖。
4. `build_agent_components` 从同一配置创建提示和工具定义；查询路径不构造模型客户端或子图。
5. 依照实际请求顺序应用图片投影、官方 Todo 提示追加、Skill 提示追加和 MCP 目录/工具投影。middleware 工具先于基础工具，保持与当前 LangChain 工厂一致。
6. 分类估算、按匹配样本校准、解析窗口容量，返回 `ContextUsage` 并渲染。

没有 Checkpoint 文件时使用空消息状态，不创建数据库。查询不执行 Agent 图或带 I/O 的 middleware hook，不更新 session 元数据、轨迹和 Checkpoint；对 pending writes 的合并仅存在于本次查询内存中。

## 6. MCP 快照与会话兼容性

v0.0.9 将 MCP 连接记录扩展为：

```text
server_id → {
    config_digest,
    catalog_digest,
    tool_schemas
}
```

`tool_schemas` 在正常 MCP 工具发现成功时生成，按公开别名排序，保存模型实际可见的 OpenAI 格式定义。`/context` 只统计 Checkpoint 中已经启用的服务，并在本地核对配置摘要；配置中尚未连接的服务仍只贡献系统目录提示。

快照不包含客户端、连接句柄或可执行工具对象。正常 `ask`/`resume` 继续通过原有流程连接并核对目录，不能凭快照直接执行远端工具。远端不可达、凭据环境变量未设置等情况不会因统计查询而触发连接；本地配置摘要变化仍会返回现有配置不一致错误。

本版按项目开发阶段约定不迁移旧 session。旧 MCP 记录缺少 `tool_schemas` 时，统计返回 `mcp_catalog_missing` 并要求新建会话，不默默漏算远端工具。当前版本的跨进程恢复属于验收范围。

## 7. 配置与 Python 接口

### 7.1 上下文容量

新增可选配置 `[model].context_window`，只接受正整数，拒绝布尔值、字符串、小数及非正数。示例是 `gpt-4o-mini` 的配置片段，不应直接套用到其他模型：

```toml
[model]
model = "gpt-4o-mini"
max_tokens = 4096
context_window = 128000
```

容量来源优先级：显式 `context_window` → 与 `ChatOpenAI.profile` 相同的内置 `max_input_tokens` 数据 → 未知。读取内置表时不初始化 HTTP 客户端，也不联网获取模型信息。`max_tokens` 仍是输出上限。

容量为 `W`、已用为 `U` 时，剩余量为 `max(0, W-U)`，总占用百分比为 `100×U/W`；不额外扣除输出预留。无法识别容量时，已用量和分类继续显示，其余指标为 `—`，面板仅追加 `Set model.context_window`。本次锁定依赖未识别 `glm-5.3-flash`，使用该模型时需按实际服务商容量显式配置。

### 7.2 应用服务

`application.py` 导出异步接口：

```python
from rs_harness.application import ContextUsage, get_context_usage

usage: ContextUsage = await get_context_usage(config, session_id)
```

| 字段 | 类型与含义 |
| --- | --- |
| `session_id`、`model` | 当前 session 标识、当前配置模型名 |
| `context_window` | 窗口容量，未知时为 `None` |
| `used_tokens` | 各分类整数估算之和 |
| `remaining_tokens`、`usage_percent` | 剩余量和总占用百分比，容量未知时为 `None` |
| `categories` | 分类列表；每项包含 `key`、`label`、`tokens`、`percent` |
| `estimation_method` | `approximate` 或 `calibrated` |

该接口返回数据，不打印终端内容。原有 `ask`、`resume`、审批状态和 CLI JSON 返回契约不因面板而扩展。

## 9. 保留边界与维护约束

- 本地估算及统一校准无法提供服务商级别的精确分类；不展示为精确账单，也不增加费用统计。
- 图片不按模型分辨率策略计费；新模型或自定义 endpoint 的窗口可能需要显式配置。
- 不提供上下文压缩、自动裁剪、自动清空消息、使用率预警任务或旧会话迁移。
- 普通交互命令和独立 Python 服务是本版入口，不改变审批输入协议。
- 后续新增改变模型输入的 middleware 时，必须同步扩展纯投影路径，并维持实际请求与统计请求的一致性测试。
