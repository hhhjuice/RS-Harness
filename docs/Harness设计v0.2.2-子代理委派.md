## 1. 目标

`task` 把自包含任务交给具有独立上下文的子代理，减少父会话中的过程消息。子代理有描述身份与职责的名称，父代理通过返回的 ID 持续追问；恢复同一父会话或重启程序后，仍可继续已有子会话。父会话只收到子代理身份、状态和本轮最终文本，子代理的完整消息与审计保存在自己的账本中。

沿用同一个 Agent Loop、单层委派和独立上下文。新建及续聊默认进入进程内后台队列，父循环立即继续；父代理通过 status 或 wait 回收结果。后台线程只在当前进程存活，进程中断后任务标记为 interrupted，子会话仍可恢复。

## 2. task 接口与输出

| 操作 | 调用示例 | 条件 |
| --- | --- | --- |
| 新建并执行 | `task(name="影像元数据检查员", prompt="检查目录中的影像元数据")` | 必须提供 name 和 prompt，不提供 session_id |
| 继续对话 | `task(session_id="子会话ID", prompt="根据刚才的结果检查坐标系")` | 必须提供 session_id 和 prompt，不接受 name |
| 查询状态 | `task(action="status", session_id="子会话ID")` | 不调用模型 |
| 等待结果 | `task(action="wait", session_id="子会话ID", timeout_ms=5000)` | 超时返回当前状态 |
| 主动关闭 | `task(action="close", session_id="子会话ID")` | 协作取消或关闭，不接受 name 或 prompt |

- `action` 默认 `run`，允许 `run`、`status`、`wait`、`close`。`run` 默认后台执行，可用 `background=false` 选择同步执行。Schema 声明参数，handler 校验操作对应的参数组合。
- 新建时名称必填：去除首尾空白后长度为 1–64 字符，不允许换行或控制字符。名称只在创建时设置，不提供重命名；名称允许重复，`session_id` 是唯一定位依据。
- `run` 的 prompt 必须非空，最多 8000 字符。旧的 `task(prompt=...)` 新建调用必须补充 name，直接调用 handler 同样遵循此规则。
- 非法、空白或不存在的 ID 返回错误，不新建替代会话。续聊与关闭前都要确认目标为当前父会话的直属子会话，且 workdir 一致。
- 关闭幂等；`closed` / `failed` 终态不能再运行。验证失败不追加用户消息，不调用模型。

成功创建或确认目标后，工具观察以固定文本头返回身份和状态，再附本轮最终答案或错误：

```text
session_id: <子会话ID>
name: 影像元数据检查员
status: running
execution_status: queued
session_status: running

<本轮答案或错误>
```

`status` 表示这次操作是否成功，取 `running` / `succeeded` / `failed`；`execution_status` 表示后台执行进度；`session_status` 表示会话生命周期，取 `running` / `closed` / `failed`。元信息放在正文前，答案截断时保留后续调用所需的 ID。目标验证前的错误返回普通错误观察，不声明未经确认的身份与状态。

## 3. 持久状态与数据流

子会话位于 `sessions/<session_id>/`，包含 `session.json`、`messages.jsonl` 和 `events.jsonl`。`session.json` 还持久化 execution 状态、execution_id、答案、错误和 worker 进程标识。`SessionState.parent_session_id` 指向父会话，新增可空字段 `name: str | None = None` 保存名称；`Session.create()` 接受名称参数。根会话和缺少 name 的旧数据仍能加载。历史无名子会话显示为“未命名子代理”并附 ID，不自动补写旧数据；旧终态子会话不重新启用。

`run()` 为根会话构造 `_task_runner`，处理创建、续聊、查询、等待和关闭；后台 worker 复用同一个 `run()` 执行子代理，不复制第二套循环。

1. **创建**：读取并渲染子提示词模板，创建绑定父 workdir 的子会话，将已脱敏的名称写入状态，并在首条 system 消息中追加一次身份名称说明；将任务置为 queued 并立即返回。
2. **续聊**：按 ID 加载并验证子会话，沿用保存的名称、system 消息、完整历史与 todos，只追加本轮 prompt 并调用 `run()`。恢复不读取提示词模板，不重复注入身份说明。
3. **查询/等待**：读取持久 execution 字段；wait 只阻塞指定 timeout，不影响任务。
4. **关闭**：queued 任务立即取消；running 任务设置 cancel_requested，当前模型/工具批次结束后由 worker 完成关闭；不追加 user 消息。

`runtime/tools.py` 的 `run_task` 负责参数组合校验与 runner 调度；`runtime/background.py` 提供按 `max_background_subagents` 限制的 FIFO daemon worker；`dispatch_tool` 沿用 task_runner 注入。子会话仍使用 `SUB_TOOLS`（八个工具减去 `task`），且不注入 runner；即使子模型调用不存在于 schema 的 task，也会得到拒绝观察，不产生孙会话。

父子共享模型客户端、工作目录、权限回调和自定义 Hooks；父子各自加载 todo 状态。每次子交互复用现有锁、权限检查、脱敏、错误分类、预算和 todo 提醒。父账本只记录 task 调用自身的参数、审计和结果，子工具调用及中间消息只写子账本。

名称写入状态、账本或日志前复用现有脱敏机制。子代理 console 通知前缀为 `[sub:<名称>|<ID>]`，名称中用于显示前缀的分隔符需转义。名称只帮助识别身份，不参与路径构造或会话定位。

父模型从历史 task 观察中恢复名称和 ID，无需新增内存注册表。进程内 `BackgroundTaskManager` 只保存运行期间的 Future 和取消事件，重启后不会假设旧 worker 仍存在。父子提示词都仍要求 `{workdir}` 占位符，名称由创建流程追加，不新增必填模板变量、配置项或工具。

## 4. 生命周期与失败语义

- 子代理返回答案只结束本轮交互，会话保持 `running`。模型超时、空响应或预算耗尽也不自动关闭；父代理可用相同 ID 再次发送 prompt，每轮重新获得 `loop.max_turns` 预算。
- 历史存在未配对工具调用时拒绝续聊，不重放旧动作；需要新建子代理继续工作。非法 ID、非直属子会话、workdir 不同或终态续聊均返回错误观察。
- `task(action="close", session_id=...)` 只关闭验证通过的目标，不影响兄弟子会话；重复关闭保留原终态。
- 公共 `close_session` 编排父子关闭：先关闭父会话并释放父锁，再逐个关闭直属子会话。已有终态保持不变，未终结子会话采用父会话终态。`Session.close()` 只关闭单会话，避免嵌套获取相同锁。
- 父会话已经终结时仍执行子清理，以支持重试。个别子会话关闭失败不阻止其他子会话清理，最终汇总错误；CLI 脚本入口返回非零退出码。
- `/close` 和 `close-session` 共用公共关闭入口；`/quit`、`/exit` 保留父子会话。`list-session` 继续只列根会话。
- 进程中断后，完整且仍运行的父子会话可继续使用；有未配对工具历史的会话不可重放。关闭父会话仍会清理能识别的直属子会话。

## 5. 验证场景

已使用受控模型客户端验证行为，包括新进程恢复和并发关闭；全量 `pytest` 的 242 项测试通过。本次未调用真实模型。验收包括：

- **名称与兼容**：新建名称必填；空白、超长、多行或含控制字符的名称被拒绝；规范化名称进入状态、system、结果与通知，敏感值被脱敏。同名子代理按 ID 区分，续聊不能改名，旧无名数据可加载，旧终态不重新启用。
- **持续交互**：同一父请求内多次续聊、跨父请求续聊和新进程恢复均复用同一子 ID、名称、历史和 todos；上轮观察进入后续上下文，system 只写一次，模板缺失不影响恢复。
- **消息隔离**：父账本仅含身份、状态和最终文本；子中间工具结果不复制给父。子写入对共享 workdir 可见，父子 todos 相互独立。
- **错误与边界**：超时、空响应和预算耗尽后可继续；非法 ID、跨父会话访问、workdir 不一致和终态续聊不会改写目标会话。未配对历史拒绝重放，只记录失败状态与审计，不追加新的用户或工具消息。
- **关闭**：主动关闭不调用模型、重复关闭幂等、兄弟会话不受影响；父关闭只清理直属子会话，已有终态保持，清理失败可重试，与正在委派的父会话并发关闭无死锁。CLI 关闭走统一入口，退出保留会话。
- **现有约束**：单次权限审批、Hooks、脱敏、图像输入、禁止再次委派及其余工具全部回归。

## 6. 边界

- 父子同进程、同 workdir，共享文件操作的影响；独立的是模型上下文与会话记录。
- 委派深度恒为 1，后台执行保持进程内同步 SDK 调用并由 daemon worker 并发调度。本次不引入 detached worker、跨进程后台服务、重命名、名称唯一性、历史迁移或单独的代理注册服务。
- 每次子交互独立消耗模型轮次预算；父模型可以发出多个 task 调用，累计成本取决于委派次数和各自轮次，不能只按父子预算相乘估算固定上界。
- 工具失败作为 observation 交给父模型恢复，禁止静默新建子会话替代失效 ID，禁止重放旧副作用。
- 遥感栅格语义仍在 MCP 边界外，本次不涉及像元解码或遥感算法。
